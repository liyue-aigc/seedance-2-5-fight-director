# 核心推导引擎（core-engine）

> 本文件是打斗脚本的**推导方法**：从任意题材的一句话剧情，推导出本场战斗独有的结构与时间轴。结构是算出来的，不是套出来的。
>
> 配套：通用动作/受力/空间/机位语法见 `grammar-library.md`；运镜词与渲染配方见 `fight-camera-library.md`；题材词汇（仙侠/科幻）见两个 playbook；`presets.md` 只是参数坐标速查，不含任何路线与时间表。

## 0. 铁律：从剧情推导，不从范式复刻

1. 先读用户这句话里**实际发生的冲突**，再决定结构。禁止先选定"成片范式"（云海闭环、五段对波、冷开场割草）再往里塞内容。
2. 每部成片的波段数、区域数、时间戳、结尾方式，必须能从设定卡逐步推出，并能向用户解释"为什么是这个数"。
3. 反模板判据（交付前自问）：
   - 遮住角色名与题材词，波段序列还能从用户原句推出来吗？
   - 把仙侠换成现代/科幻，空间路线和结尾会跟着变吗？不变就是模板化。
   - 成片里是否出现了用户没要求、但既往示例里有过的元素（云海、浮岛、断桥、法相、虫潮、轨道船坞）？出现即删。
4. 用户给的示例、参考视频、教程只提供**方法与素材**，不是让本次创作复刻其剧情结构；参考视频只借指定动作区间，不借场景与路线。
5. **比喻不是场景指令**：用户说"如潮水""像蝗群""人海""钢铁洪流"，描述的是密度、排列与运动方式，不得据此把战场改成水面、沙暴、虫巢等字面介质场景；介质与场景只由剧情明确提到的地点决定。拿不准时按用户给定地点写、用密度落实比喻。

## 1. 战斗设定卡（十组参数）

从用户描述中提取；缺失项用合理创作默认补齐并标注为创作补充，只有决定结构走向的歧义才追问（一次最多 3 个大白话问题）。

| # | 参数 | 取值（非穷举，按需新增） | 决定什么 |
|---|---|---|---|
| 1 | 主体清单 | 每个参与者：种类（人/机甲/巨兽/能量体/载具/群体）、数量、尺度、能力边界；群体按"波次单位"计 | 受力尺度、动作词汇、可清点性 |
| 2 | 力量关系 | 均势 / 量级压制 / 以弱胜强（注明靠什么：地形、机关、弱点、增援、代价）/ 个体对波次 / 追逐（一方不能或不愿正面交战）/ 守卫（保护对象是地、物、人）/ 撤退 | 波段序列、失势点、胜负走向 |
| 3 | 主导内容 | 拳脚 / 冷兵器 / 射击火力 / 超能技能 / 载具冲撞 / 混合（写明切换触发条件） | 动作成本、镜头距离、特效体系 |
| 4 | 空间模式 | 固定场地 / 单线推进 / 往返闭环 / 垂直升降 / 立体追逐 / 大范围战场 | 区域数、转场方式、锚点布置 |
| 5 | 节奏偏好 | 全程实时高速 / 一张一弛（含蓄力低速点）/ 写实短促 | 重击预算、镜头剪辑、能量曲线 |
| 6 | 目标与胜负变化 | 开场状态 → 结束状态的**唯一可读变化**（从 §4 目录选） | 决胜波段与收束方式 |
| 7 | 能力/资源系统 | 来源、射程层（贴身/近程/远程/超视距）、2–3 个标志性动作、代价与失效方式 | 生命周期写法、资源账本 |
| 8 | 场景 | 3–5 个空间锚点、介质（云/水/火/烟/沙/真空）、可破坏物、掩体与支点、光向天候 | 空间调度、环境参战、穿越语法 |
| 9 | 画风与资产 | 渲染配方（镜头库第四节）、对立配色、参考素材职责（`seedance-adaptation.md`） | 全局锁定词、素材绑定 |
| 10 | 硬约束 | 时长、画幅、帧率、音频、能否击杀/毁机、产线（直出/分段）、交付形式 | 时间预算与交付 |

**默认推导关系**（用户没说口味时）：均势→全程实时高速；量级压制且需要反转→一张一弛，最低点在反转前；个体对波次→持续轮转＋终局峰值；写实题材→写实短促。这些只是默认起点，用户一句话即可覆盖。

**必须追问的三种歧义**：①谁占上风、结局谁赢（影响波段走向）；②能否击杀/毁机（影响胜负手选型）；③战斗是否允许离开原地（影响空间模式）。其余一律自行补全。

## 2. 波段拆解

**波段定义**：一个波段 = 一次主动交换（谁发起、用什么手段、对方如何应对）＋ 一个可读的结果状态改变。没有产生状态变化的动作组合并进相邻波段。

**通用波段算子**（按剧情选用，可重复、可省略、可前置，不是固定顺序）：

| 算子 | 功能 | 必须交代 |
|---|---|---|
| 建立 | 双方、距离、锚点、威胁显形 | 力量关系一眼可读；冷开场可压缩到 1–2 秒并与接触合并 |
| 接触 | 第一次交换，确立力量关系 | 谁先动、第一次接触/落空的结果 |
| 升级 | 威胁加码：距离缩短、人数增加、火力升级、环境恶化、第二手段登场 | 加码的具体内容与压力差 |
| 失势点 | 主角方失去角度/资源/阵地/同伴，全片最低势点 | 失势的可见原因（不是"突然落下风"） |
| 转折 | 新信息、增援、弱点暴露、资源切换、地形利用 | 转折要素必须在更早波段埋过线索 |
| 决胜 | 兑现唯一胜负变化 | 提前埋线的胜负手在此完成 |
| 收束 | 结果落定、余势、世界状态确认 | 不摆拍、不切黑、不转身离场 |

**群体战（个体对波次）的波段推导**：一轮 = 五拍（发起手段 → 爆发 → 群体受冲出现密度空缺 → 反扑与一次近失 → 发起方位移到新位置）。波次密度只增不减；中段安排规模最大的一次奇观；终局必须改变战场地形或潮源，不允许普通球形爆炸收尾。轮次数由时长成本反推，不固定。

**密度逐镜锁定（实测纪律）**：无论景别，每个镜头的前景、中景、后景都要有成排单位——前景有扑到近前受冲的个体，中景潮线持续推进，后景的地面、山坡或道路被成片铺满；技能打出的空缺只允许存在一到两拍，随后由后排踏着同袍重新填满。"远景有潮、近景空无一物"或动作镜头里只剩两三只敌人，均视为失败，必须在该镜句内补写密度。

**双人/多体战的波段推导**：攻防发起次数双方等量（均势时）；每个波段结束写"结束状态卡"：位置（相对锚点）、朝向（屏幕方向）、相互距离、动量矢量、伤损/故障、资源与握持。下一波段必须从该状态接起。

## 3. 时间反推（耗时成本表）

时间戳是**输出**，不是输入。流程：列波段 → 波段内列动作 → 查成本求和 → 对照总时长 → 超预算按规则删减。

实时速度（约 24fps 观感）下的最小耗时估值，复杂动作取上限：

| 动作 | 耗时（秒） |
|---|---|
| 表情/眼神反应、短暂对峙微反应 | 0.3–0.8 |
| 单次直拳/斩击/点射（含发力与收势） | 0.4–0.8 |
| 含步法接近的一次打击 | 1.0–1.5 |
| 一次完整兵器交锋（出招→格挡→分离复位） | 1.5–2.5 |
| 反馈链（格挡→偏转→闪避→反攻 或 攻击→卸力→变向→追击） | 1.5–2.5 |
| 冲刺接敌（约 5–10 米） | 1.0–1.5 |
| 蹬地起跳到落地缓冲 | 1.5–2.5 |
| 腾空下劈＋格挡＋震退 | 2.0–3.0 |
| 坠落/俯冲穿过一个区域 | 2.0–4.0 |
| 区域转换（含遮挡转场） | 1.0–2.0 |
| 能力/武器系统完整生命周期（准备→释放→传播→相遇→响应→消散） | 2.0–4.0 |
| 对波/角力（蓄力→相遇→拉锯→反推→结果） | 4.0–7.0 |
| 胜负手全过程（脱手/破防/倒地/系统失效） | 2.0–3.0 |
| 收束（后拉/落定/结果确认） | 1.5–3.0 |
| 大远景/航拍建立 | 2.0–4.0 |

排程规则：

- 每秒主要动作不超过 3 个；每 5 秒主要交换不超过 1 个，可附带 1 个顺势动作。
- 决胜波段前后各留至少 1 秒读结果；时间戳连续、不重叠、不遗漏，结束时间等于总时长。
- 超预算时按顺序删减：删空挥与重复交换 → 合并形态相同的波段 → 减区域 → 缩小技能规模。**禁止压缩单个动作的物理时间**（不许 3 秒塞俯冲＋穿障＋落地＋决胜）。
- 张弛是排程结果：标出全片最低势点与决胜点，两点之间必须有可感知的速度/景别/力度对比；高速片用动作密度与景别切换制造呼吸，不用慢动作。

## 4. 胜负变化通用目录

默认非致命；击杀、毁机、死亡必须用户明确要求。所有胜负变化提前埋线（裂纹、告警、角度丢失、资源见底），决胜波段只兑现。

- **人/生物**：兵器脱手、关节锁死、重心破坏倒地、被击退到区域外、力竭喘息、护体/护甲破裂、击落坠势（坠落但不写死亡）、被压制无法起身、主动撤离。
- **机甲/科技**：护盾扇区过载熄灭、武器过热卡壳、推进器/关节被打停、能源/管线被切断、传感器致盲、弹药耗尽、兵器脱手、被迫停战撤离。
- **群体/战场**：指挥单位被拔除、潮源（巢塔/法阵/母舰/号角手）被毁、补给线被切断、合围被撕开缺口、守卫目标达成（守住/夺取/护送撤离）。

决胜机位必须通过 `grammar-library.md` §6 机位可行性表检查；脱手、坠势、掠过停位等高风险几何默认改用安全替代。

**收束纪律**：结尾的每个动作必须由胜负直接导致（碎兵器、破防、力竭、撤退掩护），禁止安排与战斗无关的道具或生活化动作（捡东西、接花灯、整理无关物件）；高速片的结束状态卡不得写"对峙/相对而立"，必须描述仍在进行的运动（追击、逼近、后撤、余动）。

## 5. 连续性台账

- 每个镜头/每段结尾记录六字段：**位置、朝向、距离、动量、伤损/故障、资源与握持**。
- 切镜只切相机不切世界：伤损不恢复、碎屑与残骸保留、光向与天候不变、人数不复制、武器不回手。
- 分段生成时，每段提示词开头写一行"承接状态"（上段尾帧六字段），段尾埋遮挡点（见语法库 §5），并重复绑定同一批资产。

## 6. 单段直出能力框（平台可行性，实测归纳）

单段文生视频（尤其无参考图时）的可靠区间。超出区间不是"写得再详细点"能解决的，必须走 §7 产线规则。

1. 时长内主要区域 **≤3–4 个**；新区域、新地标、新敌人类型只允许在前 60% 时长引入，**后 40% 不得出现任何新场景元素**，只能回到已建立的区域。
2. 需要观众记住的有名角色 ≤2；群体以统一材质的波次存在；需要记住的小道具（特定武器、面具、编号物件）≤1–2 件，且在前 2 秒给出清晰特写。
3. 前 2 秒必须完成：主锚点入画、力量关系可读；冷开场时第一次接触已经发生。
4. 高风险调度（默认禁用，安全替代见语法库 §6）：绕弧 180° 换位、"A 高速掠过停到 B 身后"、同帧双向高速交叉后要求精确落点、长时长垂直穿层后精确返回原点、脱手小物体跨画面长距离飞行、一镜到底中同时要求环绕＋推镜＋变焦。
5. 高风险空间：先在介质之下、穿出到介质之上、再俯瞰原点俯冲返回的三段垂直调度（云/水/雾/烟），单段直出只给简化版（语法库 §4 介质层穿越），完整版必须分段。
6. 事件密度：决胜段（最后约 3 秒）主要动作 ≤3 个；全屏特效单次持续 ≤1 秒；同一画面能量色 ≤2 系；接触点不被特效遮挡。
7. 无参考图时，角色面部、特殊武器、面具等在长时长尾部必然漂移——对策是自动产出资产图提示词（§7），而不是要求用户自行补图。
8. **受力几何检查（实测归纳）**：每个击退/踢飞/撞落写明"起点—飞行距离—落点"，三者不得重合；受力者身后紧贴障碍时，飞退方向必须避开，或先用一个位移波段把人打到开阔处再给重击。升格只拍命中瞬间，位移与落地在实时中完成（语法库 §8）。
9. **遮挡与特效时长（浅滩严格口径）**：直出版遮挡默认不超过三分之二画幅，满画 ≤0.5 秒、每段一次；全屏特效单次持续 ≤1 秒，时长上限直接写进该镜头句子（如"爆光0.8秒后迅速收束，只剩接触点残弧"）。**不设"铺满画面 1.5–2 秒"的例外开关**，用户要大场面时靠构造数量、粒子层次与镜头运动表现，不靠全屏长亮；爆光中接触点与两人轮廓必须可读。
10. **对称对轰是高风险图式（实测归纳）**，四条强制：①禁止双方同高度、静止、特效墙对墙的持续相持（模型会拍成连续5秒相同壁纸构图）——对轰必须高低错位或角度错位、至少一方在位移中施法；②两构造相撞后 1.5 秒内按"构造裂纹→交界推移→一方构造碎裂→胜者构造触及败者身体"的有序微拍写完，不许停在相持状态；③大型构造（龙/凤/兽/浪）始终在施法者体外、朝向对手，施法者不得被自己的构造包裹，护体只留贴身薄层；每个构造在同一句内写明归属与目标；④不允许全屏铺满的峰值，相撞爆光单次 ≤1 秒、句内写死时长，光源方向与两人轮廓位置写明（如"光自接触点爆开、两人在画面两侧"），禁止只写"铺满画面"。

## 7. 两条产线（自动选择，默认双交付）

- **产线 A｜省事直出**：结构在能力框内时直接给单段提示词。超出能力框时，引擎**自动降级**，不把超纲结构丢给模型：
  区域合并到 ≤3–4 个；闭环往返改单向流动；垂直穿层改单层调度；绕弧换位改固定侧面机位；跨画面脱手改近身缴械（武器落在画面内可见处）；后半段新元素前移到前 60% 或删除；群体规模按可读密度而非数量词控制。交付时用一句话注明做了哪些降级。
- **产线 B｜高保真分段**：用户要完整奇观、多区域、复杂垂直调度时，自动产出分段包：在遮挡点（爆光、介质遮满、掠过物、暗场）切开，每段 5–7 秒；每段含承接状态行、本段动作、遮挡尾帧、重复绑定的资产清单。段数由波段与成本表算出，不由固定模板决定。
- **默认交付规则**：20 秒以上或命中任一高风险项时，同时给"直出版（已自动降级）"与"分段版（高保真）"，一句话说明差异；用户明确只要其一则遵从。
- **资产图提示词**：纯文生且无角色/武器/场景参考图时，自动附带可直接用于文生图的资产提示词（角色三视图、专属武器、主场景，一主体一条、建议竖版 3:4），作为标准附件，不向用户收取额外工序。

## 8. 组装顺序

设定卡（内部推导，可简要展示）→ 波段表（含每波段结束状态卡）→ 耗时核算（时间戳）→ 逐波段配镜头/受力/特效/声音（语法库＋镜头库＋题材手册）→ 连续性台账与能力框校验 → 按 `shared-core.md` §5 组装【】分块最终提示词 → 需要时附分段包与资产图提示词。

## 9. 引擎自检清单（交付前）

- [ ] 波段序列、区域数、时间戳、结尾方式能否逐条对应回设定卡与用户原句？
- [ ] 时间戳合计是否等于总时长、无重叠无遗漏？每个动作耗时是否符合成本表？
- [ ] 胜负变化是否唯一、可读、提前埋线、非致命默认？
- [ ] 后 40% 是否无新场景元素？高风险机位是否已全部替换？区域是否 ≤3–4（直出版）？
- [ ] 六字段连续性是否逐镜衔接？伤损、资源、握持、光向是否延续？
- [ ] 是否误带了用户没要求的既往示例元素？
- [ ] 直出版与分段版是否都已按规则产出（或用户已明确只要其一）？无参考图时资产图提示词是否已附？
