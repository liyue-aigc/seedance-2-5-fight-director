# 科幻高燃战斗系统手册（题材词汇与物理）

本手册为机甲、动力装甲、赛博义体、机械兽、无人机群、太空与轨道设施战斗补充**科技因果、资源状态与科幻视觉语言**。它不是一种节奏：结构推导走 `core-engine.md`，口味坐标查 `presets.md`，通用动作/受力/空间/机位语法走 `grammar-library.md`，本手册只提供科幻题材的词汇与物理等价物。

科幻允许先进技术，不允许“科技”成为无来源瞬移、无限弹药、无限护盾或无惯性转向的借口。高燃来自：威胁升级、位置争夺、系统资源被逼到极限、一次可读的故障或破防，以及胜负后的状态代价。

## 一、坐标与科幻系统的叠加

| 科幻任务信号 | 口味坐标（presets） | 本手册负责补充 |
|---|---|---|
| 重型机甲／机械兽近身冲撞、慢重格挡、强调吨位 | 写实近身短打 | 结构传力、液压迟滞、支撑足、装甲形变、步震 |
| 动力装甲／人形机甲均势高速 1v1、推进追逐、近远程切换 | 高速均势流动 1v1 | 推进矢量、惯性、热量与弹药、护盾破防、流动中的区域转换 |
| 主炮蓄能、护盾对冲、舰炮／巨构 Boss 决胜 | 蓄力回合决胜（只借一张一弛的节奏坐标） | 用反应堆、炮膛、电容、散热与装甲替换全部灵力、法阵、剑气词汇 |
| 无人机群、机械虫潮、舰载机群、一对多清场 | 群战清场（只借波次推导） | 编队来源、火力走廊、电子干扰、补充波次、统一损毁规则 |

题材与节奏是两条正交的轴。科幻任务出现“蓄能炮”不等于仙侠画风；波段、时间轴与配额由引擎推导，视觉、受力和名词全部服从本手册。若用户指定硬科幻，进一步收紧惯性、真空声音与资源守恒；若指定超级机器人或动漫科幻，可以夸张，但仍要看见推进、支撑和系统代价。

## 二、战斗系统约定

动笔前内部锁定七项，不必全部展示，但时间轴必须与之相容：

`主体结构｜支撑/推进｜主副武器及安装位置｜防御层｜能量/弹药/热量资源｜可累积故障｜胜负手`

1. **主体结构**：人形机甲、动力装甲、履带平台、多足机械兽、无人机、战机或舰船；动作服从关节和尺度，重型机体不能像人体无迟滞后空翻。
2. **支撑与推进**：足部抓地、磁力靴、履带、多足、主推进器、姿态喷口、缆索或轨道。每次离地、急转与刹停都要写明来源。
3. **武器归属**：写清左右臂、肩架、背部、腰侧或机腹挂点；展开、换装、抛弃、断裂与再取用必须发生在画面中。
4. **防御层**：实体装甲、反应装甲、能量护盾、电子干扰、诱饵或地形掩体。每层只能处理其能处理的威胁，并有可见代价。
5. **资源状态**：弹匣、导弹数不要求逐发报数，但要有“充足→告警→受限”的可见变化；高功率武器要经历充能、后坐或结构承力、过热与冷却。
6. **故障账本**：传感器失真、某侧推进器推力下降、关节卡滞、装甲脱落、护盾扇区失效、武器过热。后续动作必须适应该故障，不能下一镜恢复如初。
7. **胜负手**：护盾过载、武器脱手、推进器失效、关节锁死、传感器致盲、能源切断、被迫撤离或失去目标区域；不默认爆机或驾驶员死亡。

## 三、科幻动作与火力状态链

### 1. 重型机甲近战

`支撑足锁定/地面承压 → 髋部与肩部带动武器或重臂 → 装甲/武器接触 → 活塞压缩、关节回弹、结构传力 → 质量移向支撑足 → 滑退、跪撑或重新稳定 → 暴露下一处进攻角度`

- 接触前让观众看见双方吨位、距离和支撑；命中后先出现结构反馈，再出现碎屑、火星和镜头短震。
- 地面响应匹配材质：混凝土龟裂、甲板凹陷、砂砾被推出沟，不让所有场景都喷同一种尘云。
- 轻型单位打重甲不靠“更用力”，而靠关节、传感器、散热口、推进器等可见弱点；弱点必须先建立。

### 2. 动力装甲／人形机甲高速交锋

`推进器点火或蹬地接近 → 一方从明确角度进攻 → 对手格挡/偏转/短喷口侧移 → 接触或落空 → 双方沿惯性分开 → 姿态喷口修正朝向 → 重新抢占射线或近战角度`

- 高速不等于全程残影。主体保持清晰，背景与掠过物表现速度；每次变向有喷口、接触物或原有角动量。
- 近战与远程切换要经过拉开距离、武器展开/收回和重新瞄准，不在同一瞬间完成拔枪、锁定、射击与收枪。
- 均势对手要主动抢角度、逼出冷却窗口、攻击受损侧，不只是等待主角连招。

### 3. 实弹、磁轨炮与定向射击

`传感器/目视获得目标 → 炮口或枪体对准、供弹/电磁轨道就绪 → 发射与后坐/结构承力 → 弹体沿可读方向传播 → 对手闪避、掩体拦截或装甲接触 → 材质响应与碎屑沿力向扩散 → 弹仓、炮管温度与射手姿态进入下一状态`

- 弹道可以快，但不能“枪口一亮、远处同时爆炸”而没有方向关系。用短尾迹、掠过物、命中先后或镜头轴线交代传播。
- 连射以一段火力压制表达，不逐发塞镜头；写清弹着点如何逼迫对手改变路线。
- 命中装甲先出现凹陷、剥落、火花或贯穿孔，再决定机体是否失衡；爆炸规模服从弹体与目标尺度。

### 4. 导弹、无人机与拦截

`舱门/挂架展开 → 点火离架 → 沿弧线或编队接近 → 目标机动/释放诱饵/电子干扰 → 拦截、近失或命中 → 爆压、碎片与编队缺口 → 烟迹、残骸和剩余单位继续运动`

- 导弹有发射位置、转弯半径与到达时间；爆炸不能先于弹体或拦截点。
- 无人机群写明母舰、舱口或远处编队来源，数量用“固定小队／持续补入的波次”而非随机复制。
- 电子干扰用锁定框抖动、传感器噪声、编队失序等可见后果表现；除非用户要主观 HUD，不让界面元素遮住主体。

### 5. 光束、等离子与蓄能主炮

`反应堆/电容把能量送入炮体 → 炮口结构展开并对准 → 核心亮度与热浪上升 → 光束/等离子沿单一射线传播 → 护盾、装甲或对向能量在清晰位置相遇 → 炮体后坐、护盾凹陷、装甲烧蚀或目标位移 → 光束收束、炮口过热、散热结构展开`

- 对冲时写交界面与推移，不把两条霓虹线固定在空中；弱势方通过护盾扇区闪烁、支撑结构变形或推进器被迫全开表现压力。
- 主炮释放后必须留下资源代价：冷却窗口、供能下降、炮口烧红、装甲熔蚀或姿态失稳。不能立刻无成本再次满功率开火。
- 光效只强调射线、接触与余热，战果显露后迅速衰减；避免全屏长亮和无体积的 LED 灯带。

### 6. 能量护盾

`发生器节点/投射器启动 → 护盾在明确范围成形 → 攻击抵达并使局部凹陷、波纹或偏折 → 负荷沿表面扩散 → 指定扇区闪烁/开裂/过载 → 局部坍缩或恢复到较弱状态 → 后续角色利用或保护该缺口`

- 先看见攻击到达护盾，再出现涟漪和报警；护盾不是覆盖全画面的彩色滤镜。
- 局部护盾与全向护盾的覆盖范围要一致；背后扇区失效后，角色不能下一镜继续从该方向无损承击。

### 7. 零重力与太空惯性

`从舱壁/残骸蹬离或推进器点火 → 沿既定矢量漂移 → 开火/碰撞改变线速度或角速度 → 姿态喷口分阶段修正 → 接触缆索、甲板或目标 → 制动并重新建立参照 → 保留仍在漂移的残骸与烟气粒子`

- 零重力没有普通“跳起落地”；没有外力就不突然转弯或刹停。推进方向、机体运动方向和镜头参考轴要能读懂。
- 武器后坐会改变轻型主体姿态；重型舰体的变化更小，但要有炮座、结构振动或姿态喷口补偿。
- 硬科幻真空外景默认压低外部爆炸声，用驾驶舱、机体结构振动、无线电和配乐传递冲击；用户要娱乐化太空歌剧时可保留风格化音效。

## 四、距离层与规模控制

科幻战斗先锁距离层：`接触距离｜近程机炮/兵器｜中程导弹/光束｜远程主炮`。改变距离必须由推进、掩体、击退或轨道运动完成。

- 武器系统数量按时长成本反推（引擎 §3）：短片只选一个主要距离层、一次反制和一个明确系统结果；30 秒通常也只用两种主要攻击方式＋一种防御机制＋一次胜负手，不展示完整武器库。
- 高燃峰值集中在一个系统突破：护盾破裂、炮体过热、推进器熄火、武器脱手或关节锁死。其余碰撞为峰值服务，并提前埋故障线索。
- 战术状态变化不等于换地图：同一设施内从外环、桁架、货舱口到核心甲板也算空间流动；区域数仍受单段能力框约束（≤3–4 个）。

## 五、场景锚点、运镜与转场

开场固定 3–5 个科幻锚点：行星地平线、太阳/恒星光向、空间站环、编号舱门、维修桁架、信标、舰船主轴、警示灯带。锚点既防止换世界，也提供速度、尺度和方向参照。

- 重型机甲以中全景、全身低机位和滞后跟随为主，保留支撑足、关节和接触点；驾驶舱或传感器特写全片通常只给 1–2 次关键决策。
- 动力装甲／高速机甲用全景和中景读清矢量，近景只给锁定、武器展开、故障告警和决定性接触。
- 太空追逐让镜头依附可见参照物移动：贴桁架侧跟、绕空间站有限环行、从残骸遮挡后接新机位。不要在无参照星空中连续旋转导致方向丢失。
- 隐形转场可用机体掠镜、喷焰、烟尘、舱门、桁架、爆散残骸或短暂传感器失真；切后延续运动矢量、相对距离、损伤、弹药/热量与光源方向。
- HUD、锁定框和驾驶舱 UI 仅在用户要求主观视角或信息确有叙事作用时使用；每次只显示一个关键信息，不用满屏界面制造“科幻感”。

## 六、视觉、材质与声音

- 默认 3D 科幻／史诗 CG：PBR 硬表面、金属粗糙度差异、装甲边缘磨损、液压与执行器、推进器体积喷焰、热变色、局部电弧、真实碎屑和体积光。风格化赛璐璐或复古特摄按用户指定覆盖。
- 一场战斗限定两套易区分的系统色。能量色绑定阵营或功能，不为每种武器随机换色；实体弹药主要靠尾迹、枪口焰和材质响应，不强加彩色光带。
- 损毁按材质：金属屈曲和剥落、复合装甲分层、玻璃龟裂、线路短路、冷却剂雾化、推进器喷焰不稳。不要把所有命中都处理成同一种球形火球。
- 声音层：环境底噪/舱体共振 → 伺服、液压、脚步与推进 → 武器启动、供弹、锁定或充能 → 接触材质、爆压与报警 → 散热、余振、无线电与音乐收束。声音要能区分重量和系统状态。

## 七、素材与 Seedance 2.5 适配

有素材时优先按职责拆分：角色/机体图锁轮廓和结构，武器图锁安装位置与形态，场景图锁空间站或城市布局，动作视频只借重心、路径与节奏，白模或预演视频可借镜头、构图、主体轨迹和表演调度。具体数量、标签与入口以 `seedance-adaptation.md` 和用户实际界面为准；没有素材不编造 `@Image`、`@Video`、白模或绿幕引用。

多素材不要争夺控制权。若机体参考图没有展示背部推进器，不擅自声称图中已有；可以把新增推进器明确标为创作补充，或改用画面中确有的支撑方式。

## 八、科幻提示词组装

组装顺序、【】分块与双产线规则统一走 `shared-core.md` §5、§6 与 `core-engine.md` §7，本手册不另立时间轴骨架。科幻题材在分块中必须落实的专属内容：

1. 【整体战斗概念】：距离层与目标（夺点、突围、逼停、守卫），胜负手是哪一种系统突破。
2. 【主体资产】：每个机体的结构、尺度、推进/支撑方式、武器挂点、防御层、系统色。
3. 【武器/能力/科技系统】：七项系统约定（§二），资源与故障账本的可见变化。
4. 【世界场景】：3–5 个科幻锚点、光向、重力/介质条件、初始距离层。
5. 【分镜时间轴】：每段一个主要攻防交换或系统变化，写清结束状态（矢量、距离、故障、资源）；时间戳由成本表反推。
6. 【全局负面约束】：无瞬移复制穿模、无无来源急转、无弹道未到先爆、无护盾/故障复原、无随机 HUD 与球形火球遮接触点。

## 九、静默检查

- 主体关节、支撑和推进方式是否与体型相符？每次急转、制动、腾空是否有外力来源？
- 武器是否从固定挂点展开，弹道/光束/导弹是否先传播后命中，后坐与热量是否留下状态？
- 护盾是否有发生器、范围、受击点、负荷扩散与破裂后果，而不是全屏滤镜？
- 距离层改变是否经过可见路径；零重力是否保持惯性与反作用？
- 双方是否都主动争夺角度、掩体、冷却窗口或受损侧，而非一方等待挨打？
- 故障账本是否延续：受损推进器、关节、传感器、装甲、弹药与冷却状态有无复原？
- 每段是否只有一个主要交换或系统变化；镜头是否让支撑、矢量和接触点可读？
- 科幻感是否来自结构、材质、系统与环境，而不是随机 HUD、霓虹光带和满屏爆炸？
